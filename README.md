# Multi-Agent SQL Generation System

This system uses multiple AI agents to process PDF content and generate SQL INSERT queries for a lessons table with JSONB sections.

## System Architecture

The system consists of three main agents working together:

### 1. ContentGenerator Agent
- **Purpose**: Extracts and structures content from PDF documents
- **Input**: PDF chunks with metadata
- **Output**: Structured sections with type, content, and title

### 2. DataTransformer Agent
- **Purpose**: Transforms structured sections into lesson objects
- **Input**: Structured sections (JSON format)
- **Output**: Validated lesson objects with proper data types

### 3. SQLGenerator Agent
- **Purpose**: Generates SQL INSERT queries for the lessons table
- **Input**: Lesson objects
- **Output**: SQL INSERT queries with JSONB formatted sections

### 4. MultiAgentOrchestrator
- **Purpose**: Coordinates all agents in the pipeline
- **Input**: PDF file or existing JSON data
- **Output**: Complete SQL queries and metadata

## Database Schema

The system generates SQL for a `lessons` table with the following structure:

```sql
CREATE TABLE lessons (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    course_id UUID NOT NULL,
    title VARCHAR(255) NOT NULL,
    is_active BOOLEAN DEFAULT true,
    sections JSONB NOT NULL DEFAULT '[]'::jsonb,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

### JSONB Sections Format

The `sections` column stores an array of JSON objects with this structure:

```json
[
  {
    "type": "text",
    "content": "Lesson content here...",
    "title": "Section Title"
  }
]
```

## Usage

### Complete Pipeline (PDF → SQL)

```python
from agents.MultiAgentOrchestrator import MultiAgentOrchestrator

# Initialize the orchestrator
orchestrator = MultiAgentOrchestrator()

# Process PDF and generate SQL
results = orchestrator.process_pdf_to_sql(
    pdf_path="lesson1.pdf",
    subject="Mathematics",
    course_id=None,  # Auto-generated if not provided
    max_chunks=3     # Optional: limit chunks to process
)

print(f"Generated {results['total_sql_queries']} SQL queries")
```

### From Existing Data

```python
# Generate SQL from existing structured data
results = orchestrator.generate_sql_from_existing_data(
    json_file_path="output/structured_sections_maths.json",
    course_id="your-course-uuid"
)
```

## Output Files

The system generates three types of output files:

1. **Structured Sections** (`structured_sections_*.json`)
   - Original structured content from PDF processing

2. **Lessons Data** (`lessons_*.json`)
   - Transformed lesson objects with proper data types

3. **SQL Queries** (`sql_queries_*.sql`)
   - Ready-to-execute SQL INSERT statements

## Features

### Data Validation
- Validates lesson titles and content
- Ensures sections have required fields
- Logs warnings for invalid data

### SQL Safety
- Escapes single quotes in text content
- Generates proper UUIDs for IDs
- Uses parameterized JSONB format

### Logging
- Comprehensive logging at all stages
- Error tracking and debugging information
- Progress tracking for large documents

### Flexibility
- Supports custom course IDs
- Configurable chunk processing limits
- Works with existing JSON data

## Error Handling

The system includes comprehensive error handling:

- **PDF Processing**: Handles corrupted or unreadable PDFs
- **Data Validation**: Skips invalid lessons with warnings
- **SQL Generation**: Escapes special characters and handles large content
- **File Operations**: Creates directories and handles file I/O errors

## Logging Configuration

All agents use the centralized logger configuration:

```python
from logger.config import logger

logger.info("Processing started")
logger.warning("Invalid data detected")
logger.error("Processing failed")
```

## Dependencies

- `pydantic`: Data validation and serialization

- `json`: JSON processing
- `os`: File system operations

## Running the System

1. Ensure all dependencies are installed
2. Place your PDF file in the project directory
3. Run the main script:

```bash
python main.py
```

The system will process the PDF and generate all output files in the `output/` directory.
